# Спецификация: семантический слой интентов колонки (laya + гибрид)

Статус: черновик-спека (решение владельца tg#27815/27820/27825/27828: сначала описание, без изменений в проде).
Автор: SemanticIntents, 2026-11-06. Всё, что помечено «замерено», получено на живых системах в этот день.

## 1. Цель

Заменить единственный regex+score-скорер (`/src/backend/ha-intents.ts` в контейнере `aisis-yandex-quasar-1`, 841 строка) гибридом:

1. **Быстрый путь** — точные/stem-совпадения текущего скорера исполняются мгновенно (как сейчас).
2. **Серая зона** (fuzzy 0.5–0.9 и no-match на коротких командах) — классификация через **laya** (локальный классификатор task-cli, уже работает на этой машине): домен + уверенность + воздержание.
3. **Уточнение** — при неоднозначности колонка задаёт вопрос с вариантами (по образцу `ask_user` календарь-бота), а не молчит и не угадывает.
4. **Фолбэк** — llm-хвост уходит в мозг (claude_primary) как сегодня. Текущий скорер остаётся всегда.

Обучение — обязательная часть (владелец: «по крайней мере черновые, но нужно обучение»).

- Что берём: (а) список причин отказа `no_match/ambiguous/missing_capture` вместо «наиболее похожего»; (б) `ask_user` с вариантами и поглощение ответа; (в) типизированные слоты; (г) принцип «совпадение текста не даёт права на запись/действие» — у нас аналог: уверенный laya-хит только по безопасным доменам (light/volume/media/timer/query), рискованные — всегда уточнение.

## 4. laya: что это и замеры

- Пакет `laya` (PyPI, 0.3.29) + `tasklib.classify_server`. Тёплый сервер уже крутится на этой машине (guardian-venv, CPU-only: `CUDA_VISIBLE_DEVICES=` пуст, 2 потока, RSS ≈ 2.7 ГБ): процесс `python -P -m tasklib.classify_server`, сокет `~/.local/state/task-cli/classify/laya-0.23.1.sock` (каталог 0700, сокет 0600). tg-cli ходит туда же (справка: `~/xp/tg-cli/README.md` §Laya; таймаут warm 3000 мс, cold ≤75 c).
- Модели: `convaiinnovations/laya-multilingual` (мультиязычная — наша), `laya-typed-decisions` (типизированные решения). Протокол: JSON-строка через AF_UNIX: `{"op":"predict","message":...,"questions":{...}}`; `questions` — своя мини-схема: `{"type":"choice","instructions":...,"criteria":{метка:описание}}` + `score`/`noul`. Ответ содержит калиброванные вероятности.
- **Замер задержки (этот день, warm, 8 русских фраз)**: 511–598 мс, первая после простоя ~988 мс. Модель в ответе: `laya-rl-agent`.
- **Замер качества zero-shot (мои англ. criteria, без обучения)**: 8/8 отвечено, но метки слабые: «включи свет на кухне»→climate, «который час»→chitchat, «убавь яркость в спальне»→chitchat. Вывод: zero-shot для наших доменов непригоден, нужен тренинг — что совпадает с требованием владельца.
- **Тренинг уже в пакете**: `laya-train --data train.jsonl --eval holdout.jsonl --label-column ... --loss {soft-ce,rlcd} --target-error ... --min-abstain-n ...` (fine-tune чекпойнта, поддержка воздержания), оценка `laya-evals run|compare`. Кривая обучения → свой чекпойнт laya для домоменов колонки.
- Горизонт: обратный SSH-туннель `laya-ubuntu.sock` на 65.21.40.51 уже обслуживает удалённую копию — паттерн «laya где-то ещё» отработан (`laya.socket` / `TG_LAYA_SOCKET` в tg-cli).
- Доступ из контейнера: сокет приватный, в контейнер не маунтить напрямую. Канал: маленький read-only эндпойнт в хост-овом `adapter.py` (aiohttp, `127.0.0.1:31117`, туда контейнер уже ходит) → проксирует в unix-сокет laya. Альтернатива: отдельный systemd-прокси. Решение в имплементации.

## 5. Архитектура

### Основной вариант (B): regex-фастпат + laya в серой зоне

```
STT-текст
  └─ scoreIntent() [ha-intents.ts, без изменений]
       ├─ score ≥ 0.9            → исполнить (мгновенно, 0 мс)
       ├─ math/query-детерминизм → как сегодня
       ├─ 0.5 ≤ score < 0.9      → laya classify (серая зона, ~0.6 с)
       │     ├─ domain ∈ безопасные, conf ≥ θ_exec  → исполнить (модуль домена)
       │     ├─ conf < θ_clar или abstain           → уточнение с вариантами (ask-паттерн)
       │     └─ laya недоступен/таймаут             → текущее поведение скорера (fail-open)
       └─ score < 0.5             → laya: это команда домена?
             ├─ да, уверенно      → уточнение с вариантами (не исполнение!)
             └─ нет / abstain     → мозг claude_primary (как сегодня)
```

- `θ_exec/θ_clar` калибруются на корпусе (laya даёт калиброванные вероятности + воздержание).
- Бюджет задержки серой зоны: laya ~0.55 с (замер) + сокет/прокси ~30–50 мс → поворот ≤1.5 с с TTS-зачином; для мгновенных путей ничего не меняется (0 мс).
- Новый модуль: `/src/backend/semantic-intents.ts` (схема questions под домены колонки, клиент прокси, пороги, лог решений). `ha-intents.ts` остаётся фастпатом и фолбэком. Флаг `SEMANTIC_INTENTS=off|shadow|on`: shadow — только лог расхождений.

### Вариант A (резерв, не main-line): Claude-классификация одним вызовом

Haiku-класс, system prompt + каталог действий + few-shots; латентность ~0.3–0.6 с. Инфраструктура готова: 3 ключа, failover 429→cooldown (60 с, billing 3600 с) в `claude_primary.py`. Цена: Haiku 4.5 — $1/$5 за MTok in/out (platform.claude.com), Haiku 5.5 — $0.10/$0.50 (benchlm.ai, 2026-11). Диалог серой зоны ≈ 2.5k in + 150 out ≈ **$0.003** (4.5) / **$0.0003** (5.5); при 100 серых фраз/день ≈ $9/мес / <$1/мес. Использовать только если laya недоступен длительно (по решению владельца), не по умолчанию.

### Вариант C: эмбеддинги через аккаунты — отвергнут

У Anthropic **нет embeddings API** (docs.anthropic.com: «does not offer its own embedding model», рекомендуют Voyage AI). На аккаунтах владельца эмбеддингов нет — вариант отпадает.

## 6. Каталог действий колонки (DSL)

Подмножество DSL календарь-бота, один файл `backend/yandex/action-catalog.json` (генерится из корпусов, версия явная):

```json
{
  "version": 1,
  "actions": [
    {
      "id": "light.set_room",
      "risk": "safe",
      "slots": {"room": "enum[Гостиная,Кухня,...]", "state": "enum[on,off,toggle]"},
      "examples+": ["включи свет на кухне", "выключи люстру в гостиной"],
      "examples-": ["выключи всё на ночь"],
      "steps": [{"kind": "ha_call", "service": "light/turn_on", "slot_map": "..."}],
      "clarify": "Свет включить или выключить? В какой комнате?"
    }
  ]
}
```

Из этого же каталога: (а) `criteria` для questions laya (метка=action_id), (б) варианты уточнения, (в) корпус-тесты examples±. Рискованные действия (безопасность, финансы, чужие устройства) — `risk: "confirm"`, всегда уточнение/подтверждение.

## 7. Обучение (обязательная часть, tg#27828)

1. **Сбор**: каждый поворот логирует `{ts, stt_text, путь (fast/laya/clarify/llm), вердикт laya, исход (executed|clarified|llm|error)}` в jsonl-стор (приватный, как корпус календарь-бота; в git — только синтетика/агрегаты).
2. **Точки коррекции**: (а) ответ владельца в TG-репорте «нет, надо было X» → фраза уходит в стор с правильной меткой X; (б) кнопка на панели (dashboard.py) «исправить разметку» на карточке поворота; (в) уточнение колонки, где владелец выбрал вариант, → позитивная пара.
3. **Цикл**: стор → `train.jsonl` + holdout → `laya-train` (fine-tune laya-multilingual, воздержание `--target-error`) → `laya-evals compare` против предыдущего чекпойнта → катим новый чекпойнт на classify-server (отдельный сокет `laya-speaker-*.sock`, не трогаем guardian) → shadow-прогон → on.
4. **Регрессия**: корпус 363 обязателен в CI-раннере (расширение `run_corpus.mts`); порог: без ухудшения по cmd/math, рост покрытия на llm/clarify-фразах, Latency P95 серой зоны ≤ 1.5 с.
5. **Live-метрики**: доля fast / laya-exec / clarify / llm; доля исправлений владельца; WER-стратификация по STT (тренировать на реальных транскриптах GigaAM, не на чистом тексте).

## 8. Миграция

1. Эндпойнт-прокси laya в `adapter.py` (хост) + `semantic-intents.ts` (контейнер) с флагом `shadow`.
2. Неделя shadow: лог расхождений со скорером, ручная разметка, первый `laya-train` на корпусе 363 + собранных фразах.
3. Включение `on` только для серой зоны 0.5–0.9; exact-путь не трогаем.
4. Откат: `SEMANTIC_INTENTS=off` — поведение идентично сегодняшнему.
